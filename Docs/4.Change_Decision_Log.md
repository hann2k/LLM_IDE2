# LLM IDE Change Log / Decision Log v0.1

## 1. 문서 목적

이 문서는 LLM IDE 개발 과정에서 발생한 주요 결정과 변경 이력을 기록한다.

목적은 다음과 같다.

* 왜 구조가 바뀌었는지 기록한다.
* 어떤 결정이 현재 기준선에 반영되었는지 추적한다.
* Codex 개발 기준이 흔들리지 않도록 한다.
* 향후 변경 시 과거 의사결정의 맥락을 확인할 수 있게 한다.

이 문서는 다음 두 영역으로 구성한다.

```text
Decision Log
- 제품 방향, 아키텍처, 원칙에 대한 결정 기록

Change Log
- 문서 버전별 변경 내역 기록
```

## DEC-001. API 기반 IDE로 새로 구축한다

### 결정

기존 구현을 전환하거나 유지하지 않고, API 기반 프로젝트 상태 관리 IDE를 새로 구축한다.

### 배경

초기 기준에서 사용 가능한 애플리케이션 소스는 없었다.
따라서 기존 구현을 고치기보다, 새 구조를 기준으로 설계하는 것이 적절했다.

### 결정 내용

```text
프로젝트 상태는 IDE가 기억한다.
AI는 매 요청마다 필요한 맥락을 주입받아 실행된다.
```

### 영향

* LLM 장기 세션에 의존하지 않는다.
* Project Runtime이 장기성을 담당한다.
* 맥락 빌더가 핵심 엔진이 된다.

* `LlmIde.Wpf`는 후속 UI 계층이 된다.

```text
Primary Store:
- conversations/conversation.db

Auxiliary Store:
- conversations/messages.jsonl
```

### 배경

SQLite는 조회, 연결, 추적에 적합하다.

### 영향

* request_id가 SQLite와 JSONL/JSON 기록을 연결한다.
* conversation_turns, conversation_messages, context_packages를 사용한다.
* 추가 전용 로그도 유지한다.

## DEC-013. 장기 대화 관리는 요약 + 창를 기본 전략으로 한다

### 결정

LLM IDE의 기본 맥락 관리 전략은 `요약 + 창`다.

```text
원본 대화 로그
+ 롤링 맥락 요약
+ 최근 대화 창
```

### 채택 알고리즘

| 알고리즘                        | 적용 여부 | 역할                         |
| --------------------------- | ----: | -------------------------- |
| Sliding Window              | 부분 채택 | 최근 대화 창 구현           |
| Conversation Summary Buffer |    채택 | 롤링 맥락 요약 생성 |
| 요약 + 창            | 기본 전략 | 장기 대화 관리                   |
| Session-based RAG           |    보류 | File Store 이후 검토           |

### 영향

* 과거 전체 대화 원문은 매 요청에 넣지 않는다.
* 과거 맥락은 롤링 맥락 요약로 주입한다.
* 최근 대화는 제한된 원문 윈도우로 주입한다.
* 현재 사용자 요청은 항상 원문으로 주입한다.

### 상태


* 과거 summary는 `rolling-context/history/`에 보존한다.

## DEC-015. Compression 실패는 Chat 실패가 아니다

### 결정

압축 요청가 실패해도 사용자 chat 응답은 유지한다.

### 실패 처리

```text
사용자 응답 성공
원본 대화 로그 저장 성공
압축 요청 실패
```

결과:

* 사용자 응답 유지
* 원본 사용자 / AI 메시지 유지
* 기존 `current.md` 유지
* 요청 로그에 실패 기록
* 다음 chat은 기존 Summary 사용

### 금지 사항

* Compression 실패 때문에 사용자 응답을 폐기하지 않는다.
* 원본 대화 로그를 롤백하지 않는다.
* 빈 Summary로 current.md를 덮어쓰지 않는다.

### 상태

```text
확정
```

## DEC-036. 대화 저장 ID는 프로젝트별 순번 기반으로 생성한다

### 결정

신규 conversation request_id와 message_id는 GUID 기반 문자열 대신 프로젝트별 숫자 순번 문자열로 생성한다.

```text
request_id: 1, 2, 3, 4 ...
message_id: 1, 2, 3, 4 ...
```

### 배경

GUID 기반 ID는 고유성은 높지만 사람이 대화 저장 순서를 확인하기 어렵다.

## DEC-046. Agent Loop와 fetch_url 도구 도입

### 결정

사용자 입력 1회로 LLM·도구 간 다회차 주고받기를 처리하는 Agent Loop를 추가한다.
LLM은 URL을 직접 열지 않고, URL 접근이 필요하면 `tool_request` JSON을 반환하면 LLM_IDE의 도구(`fetch_url`)가 대신 수행한다.

### 결정 내용

* Core에 `IAgentLoop`/`AgentLoop`, `IChatModelClient`, `IAgentTool`/`IAgentToolHost`/`AgentToolHost`, 관련 모델(AgentTurn, AgentToolRequest/Result, AgentRunRequest/Result, StopReason 등)을 둔다.
* LLM 응답은 `{"type":"final",...}` 또는 `{"type":"tool_request",...}` JSON으로 제한한다. 파싱 실패는 `ModelError`, 알 수 없는 type/tool은 `InvalidToolRequest`로 중지한다.

### fetch_url 보안

* 허용 스킴: http, https. 차단: file/ftp/data/javascript 등.
* 차단 호스트/대역: localhost, 0.0.0.0, 루프백(127.0.0.0/8, ::1), 사설(10/8, 172.16/12, 192.168/16), link-local(169.254/16, fe80::/10), unique-local(fc00::/7), 빈 URL, 과도하게 긴 URL.

* 로그에는 전체 URL을 남기지 않고 host 정도만 남긴다. (query string의 secret 노출 방지)
