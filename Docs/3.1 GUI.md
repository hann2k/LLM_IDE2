# LLM IDE GUI 설계 v0.1 (Phase 9 WPF)

## 1. 문서 목적

이 문서는 Phase 9 WPF GUI의 화면 구성과 동작을 정리한다.

* 비즈니스 로직은 Core에만 둔다.
* WPF는 Core 서비스를 호출하는 UI 계층이다.
* 화면 단위로 설계를 기록하고, 구현 진행에 따라 갱신한다.

관련 기준 문서:

* `Docs/2.Architecture_Baseline.md`
* `Docs/3.Development_Roadmap.md`

## 2. 메인 윈도우 레이아웃

메인 윈도우는 상단 메뉴 + 3분할 본문으로 구성한다.

```text
[상단 메뉴 바]
 ├─ 프로젝트 (생성 / 이름변경 / 복제 / 삭제)
 └─ 편집 (기준 / LLM)   ※ 공통 룰 편집 항목은 제거됨 (DEC-077)

[본문 3분할]
 ├─ 좌측: 프로젝트 목록
 ├─ 중앙: 선택된 대화 목록
 └─ 우측: 아티팩트 목록
```

## 3. 프로젝트 메뉴 다이얼로그

### 3.1 단일 다이얼로그 원칙

`프로젝트` 메뉴의 하위 기능(생성 / 이름변경 / 삭제)은 **1개의 다이얼로그**(`ProjectDialog`)로 처리한다.

다이얼로그는 모드(`ProjectDialogMode`)에 따라 표시 항목과 버튼을 전환한다.

```text
ProjectDialogMode
 ├─ Create  (생성)
 ├─ Rename  (이름변경)
 └─ Delete  (삭제)
```

### 3.2 Create 모드

생성 입력 항목을 표시한다. (pID는 사용자 입력 없이 시스템이 자동 생성)

| 항목 | 설명 |
| --- | --- |
| Name | 사용자 표시 이름 |
| 시작위치 | 프로젝트를 만들 상위 폴더 (`찾기` 버튼). 실제 폴더명은 자동 생성된 pID를 사용한다. |
| API 키 | 기본 프로바이더 API 키 (생성 시 `providers.json`에 저장) |
| 대화종류 | 체크: 장기 대화 / 해제: 1회성 대화 (기본 체크) |

* pID는 프로젝트 등록소의 최대 숫자 pID + 1로 자동 생성한다. (`ProjectRegistryService.NextProjectPId`)
* 폴더 경로는 `<시작위치>/<pID>`로 만든다. (시작위치 미지정 시 프로그램 루트 하위)

버튼: `[생성] [취소]`

동작: `ProjectInitializer.Initialize(...)` 후 대화종류와 API 키를 저장하고, 목록 갱신 및 신규 프로젝트 선택.

### 3.3 Rename 모드

`Name` 항목만 표시한다. (pID/경로는 표시하지 않음)

버튼: `[수정] [취소]`

동작: `ProjectRegistryService.Rename(pID, newName)` 호출 후 목록 갱신.

### 3.4 Delete 모드

다음 안내 문구를 표시한다.

```text
안내: 정말 삭제하시겠습니까? 이 결정은 되돌릴 수 없습니다.
```

버튼: `[삭제] [취소]`

동작:

* `[삭제]`(확인 버튼)를 눌러 확정하면 프로젝트를 삭제한다.
* 프로젝트 삭제는 **프로젝트 등록소 목록에서 제거**하고, **해당 폴더 및 하위 파일을 모두 삭제**한다. (아키텍처 기준의 `delete`)
* 삭제 전 SQLite 연결 풀을 정리한다. (`SqliteConnection.ClearAllPools()`)

#### API Key가 존재하는 경우

삭제 실행 중 프로젝트에 사용중인 API Key가 확인되면 추가 안내문구와 체크박스를 표시한다. (DEC-022 / 아키텍처 기준 28의 `--confirm-api-key-delete` GUI 대응)

```text
안내문구: 사용중인 API 키도 같이 삭제됩니다.
체크박스: 사용중인 API 키도 같이 삭제됩니다.
```

* 체크박스가 `true`이고 `[삭제]`(확인 버튼)를 누른 경우에만 프로젝트를 삭제한다.
* 그 외에는 삭제를 실행하지 않고 "프로젝트 삭제가 취소되었습니다." 메시지 박스를 표시한다.

### 3.5 공통 동작

* `[취소]`는 변경 없이 다이얼로그를 닫는다.
* 오류는 메시지 박스로 표시하고 본 작업을 중단한다.
* Rename/복제/Delete는 선택된 프로젝트가 있을 때만 활성화한다.

### 3.6 복제

`프로젝트 > 복제`는 선택 프로젝트를 복제한다. (별도 다이얼로그 없음)

* 동일한 시작위치(상위 폴더)에 새 숫자 pID로 폴더를 만든다.
* 원본 폴더의 모든 내용을 재귀 복사한다. (복사 전 `SqliteConnection.ClearAllPools()`)
* 등록소에 새 항목을 추가하고 새 프로젝트를 선택한다.

## 4. 편집 메뉴 다이얼로그

### 4.1 단일 편집 다이얼로그 원칙

`편집` 메뉴의 모든 항목은 **1개의 편집 다이얼로그**(`EditDialog`)로 처리한다.

* 상단 제목(Window Title)은 편집 중인 파일 경로를 표시한다.
* 본문은 텍스트 편집기(여러 줄 입력)다.
* 버튼은 `[저장] [취소]`다.
* `[저장]`은 편집 내용을 파일에 기록한다.
* `[취소]`는 변경 없이 닫는다.
* 모든 편집 항목은 프로젝트가 선택된 경우에만 활성화한다.

### 4.2 편집 대상

> 갱신([[DEC-076]], [[DEC-077]]): 공통 룰 4종(아티팩트/압축/시스템/중요도) 편집 항목은 **편집 메뉴에서 제거**되었다. 공통 정책은 앱 루트 `<programRoot>/policies/`에 있고 개발사가 배포 시 텍스트로 수정한다. 편집 메뉴에는 프로젝트 고유 **기준**과, 공통 프로바이더를 관리하는 **LLM**만 남는다.

| 메뉴 | 대상 | 비고 |
| --- | --- | --- |
| 기준 | `<ProjectRoot>/.llmide/criteria.json` | 줄 단위 편집(`EditDialog`), 프로젝트별 |
| LLM | `<programRoot>/settings/providers.json` | 프로바이더 등록/편집/삭제 + 기본 선택(`ProviderManagerDialog`), 공통 |

> API 키는 편집>LLM(공통 프로바이더 관리) 또는 프로젝트 생성 시 입력한다. (3.2 참조)

### 4.3 동작

* 기준: `criteria.json`을 줄 단위로 편집한다(§4.4). 단일 편집기, 미리보기 없음.
* LLM: `ProviderManagerDialog`(DataGrid: 이름/API키/모델/엔드포인트)로 공통 프로바이더를 추가/편집/삭제하고 기본 프로바이더를 고른다. 저장 시 공통 `providers.json`에 기록한다.
* 오류는 메시지 박스로 표시하고 본 작업을 중단한다.

### 4.4 기준(criteria) 줄 단위 편집

기준은 `criteria.json` 원본을 통째로 제시하지 않고, **한 줄에 기준 하나**로 편집한다.

* 편집기에는 기존 기준의 제목을 한 줄에 하나씩 표시한다.
* 저장 시 각 비어있지 않은 줄을 기준 1개로 잡아 프로그램이 `criteria.json`을 재구성한다.
* 재구성되는 각 기준은 `상태 = active`, `우선순위 = normal`로 저장하며, 식별자는 새로 생성한다.
* 줄 → 기준 매핑 로직은 Core(`CriteriaService.ReplaceFromLines`)에 둔다.

## 4.5 도구관리 메뉴

`도구관리`는 하위 항목 없는 단일 메뉴로, LLM이 사용할 수 있는 도구 목록 창(`ToolManagerDialog`)을 연다.

* 창은 **조회 전용**이다. 도구는 코드 구현 또는 외부 도구 연동을 코드에서 명시적으로 구현해야 하므로, 추가/수정/삭제 기능은 두지 않는다.
* 도구 목록은 도구 호스트(`AgentToolHostFactory`가 만든 `IAgentToolHost`)의 `ListTools()`에서 가져온다. (감독 allowlist가 적용된 실제 사용 가능 도구)
* 각 항목은 도구 이름, 설명, 인자를 표시한다.
* 현재 도구:

| 도구 | 이름(name) | 설명 |
| --- | --- | --- |
| url Reader | `fetch_url` | 주어진 URL을 가져와 본문 텍스트를 반환한다. |
| web search | `web_search` | 검색어로 웹을 검색하고 제목/URL/요약 목록을 반환한다. |

* 버튼은 `[닫기]`만 둔다.

## 5. 채팅 입력창

입력창은 MainWindow에 임베드된 오버레이가 아니라 **독립 팝업 창**(`ChatInputWindow`)이다. 다른 편집기처럼 OS 기본 창 크롬으로 이동·크기조절한다. (MainWindow에 종속된 소유 창이며 작업표시줄에는 표시하지 않는다.)

### 5.1 표시와 닫기

* 입력창은 평소 닫혀 있고 MainWindow에서 `[ENTER]`를 누르면 팝업으로 열린다. (프로젝트가 선택된 경우)
* 이미 열려 있으면 다시 활성화(포커스)한다.
* `[ESC]`를 누르면 창이 숨겨지지만 입력한 텍스트는 유지한다. 다시 `[ENTER]`를 누르면 같은 창이 다시 보이고 텍스트도 유지된다.
* 창 닫기(X)는 창을 실제로 닫는다. 다음에 `[ENTER]`를 누르면 새로 연다.

### 5.2 입력 동작

* 텍스트가 입력된 상태에서 `[ENTER]` → LLM에 전송한다.
* `[SHIFT]+[ENTER]` → 줄바꿈으로 동작한다.
* 텍스트가 없거나 공백계열 문자만 있으면 전송하지 않고 창을 숨긴다. "전송되지 않고 닫혔습니다." 메시지 박스를 표시한다.
* 전송에 성공하면 입력 텍스트를 지우고 창을 숨긴다. (응답은 MainWindow 대화 목록에 스트리밍된다.)
* 전송 중에는 새 전송을 받지 않는다. (전송 실패로 대화가 기록되지 않았으면 입력 텍스트를 복원해 재시도할 수 있게 창을 다시 띄운다.)

### 5.3 크기/위치

* OS 기본 창 크롬으로 제목 표시줄 드래그 이동, 가장자리/모서리 드래그 크기조절을 한다. (별도 드래그 핸들·크기조절 그립 없음)
* 주요 입력(user) 영역은 창 크기에 따라 동적으로 늘어난다. (Grid `*` 행)

### 5.4 프로바이더 선택

* 상단에 프로바이더 콤보박스를 둔다. 창을 열 때마다 현재 프로젝트 기준으로 채운다.
* 등록된 프로바이더(`providers.json`의 `Providers`)를 나열하고, 현재 기본 프로바이더(`DefaultProvider`)를 선택 상태로 표시한다.
* 다른 프로바이더를 선택하면 기본 프로바이더를 변경해 저장한다. 다음 전송부터 적용된다.

### 5.5 수동대화 추가 (입력창 통합)

* 프로바이더 콤보박스 옆에 `수동대화 추가` 체크박스를 둔다.
* 체크하면:
  * 사용자 입력창 아래에 `assistant:` 입력창이 나타난다. user/assistant 입력 영역은 높이를 반반(50/50)으로 나눈다.
  * 하단 우측에 `[등록]` 버튼이 나타난다.
  * 이때 `[ENTER]`는 전송이 아니라 줄바꿈으로 동작한다. (등록은 `[등록]` 버튼으로만)
* `[등록]`은 user/assistant 두 입력을 받아 실제 LLM 호출 없이 완료된 대화 turn으로 기록한다. (`ChatService.AddManualConversation`, `RequestType=manual`, 압축 생략)
* user/assistant 중 하나라도 비어 있으면 추가하지 않는다.
* 등록 후 두 입력을 비우고 입력창은 열린 채로 유지한다. (연속 추가 가능)
* 추가된 대화는 목록에 일반 대화처럼 표시되고 이후 채팅의 최근 맥락 주입 대상에 포함된다.
* (별도의 `대화추가` 메뉴는 두지 않는다. 본 입력창 기능으로 통합되었다.)

## 6. 대화 목록과 응답 처리

* 기본 데이터 동작은 CLI에 구현된 `ChatService`(스트리밍)를 그대로 사용한다.
* 전송에 성공하고 LLM 응답이 시작되면 대화 목록에 행을 하나 추가한다. 새 행은 목록 맨 아래에 붙이고 자동으로 스크롤한다.
* 응답 텍스트는 행의 응답 칸에 실시간으로 표시되고, 완료 시 파싱하여 필요한 내용만 남긴다.
* 발화자(사용자) 내용은 발화내용 열에 표시하고, 작성일시도 `[yyyy-MM-dd HH:mm:ss.fff]` 형식으로 표시한다.
* LLM 응답에서 중요도 태그를 파싱하여 중요도 열(0~10)에 표시한다.
* 대화 목록의 제목줄(열 머리글)은 패널 좌상단(0,0)에서 시작하고, 머리글 글꼴은 12pt다. ("선택된 대화 목록" 줄은 두지 않는다.)
* LLM 응답 열은 내용을 마크다운으로 렌더링해 표시한다. (Markdig.Wpf로 FlowDocument 변환 후 읽기 전용 RichTextBox에 표시, 내부 스크롤 없이 행 높이를 모든 내용이 보이도록 가변으로 조절. 링크 클릭 시 기본 브라우저로 연다.)
* 행(셀) 선택 시 강조색은 기본 파란색 대신 연한 회색톤(#EEEEEE)으로 표시한다.
* 중요도 열 안에는 `삭제` 버튼을 둔다. 클릭하면 확인 후 해당 대화를 삭제한다.
  * 단, 중요도가 5 이상이면 삭제 버튼을 숨긴다. (중요도를 낮추면 다시 보인다 — 슬라이더 변경에 실시간 반응)
  * 삭제 대상: 대화 turn, 메시지, 맥락 패키지, 도구 호출 로그, 그리고 연결된 압축 turn. (JSONL과 SQLite 양쪽)
  * 롤링 맥락 요약은 누적 체인이 깨지지 않도록 그대로 둔다.
  * 삭제 후 해당 행을 목록에서 제거한다. 확인을 취소하면 아무 변경도 하지 않는다.
* LLM 응답 셀에서 텍스트를 드래그 선택하고 우클릭 → `아티팩트로 추출`로 선택 영역을 아티팩트로 저장할 수 있다. (6.2 참조)
* 중요도 슬라이더를 움직이면 표시되는 숫자도 함께 변경된다.
* 각 대화 행에 대화 ID(요청 ID)를 표시한다. (압축 추가요청 번호는 표시하지 않는다.)
* 대화 목록 하단에 별도 스크롤바 라벨은 두지 않는다.
* 대화 로드(최초 표시·프로젝트 전환) 시 가장 하단 대화가 보이도록 한 번 스크롤한다.

### 6.1 열 잠금과 중요도 편집

* 발화내용 열과 LLM 응답 열은 잠금(읽기 전용) 상태로 유지한다.
* 중요도 열만 사용자가 나중에 수정할 수 있다. WPF 내장 `Slider`(0~10 정수, 1단위 스냅)로 편집한다. (별도 슬라이더 라이브러리는 사용하지 않음)
* 슬라이더 값은 현재 숫자와 함께 표시한다.
* 마우스 드래그는 **드래그가 끝날 때** 한 번 저장하고, 키보드 조작은 즉시 저장한다.
* 데이터 바인딩/행 재활용 등 사용자 조작이 아닌 변경은 저장하지 않는다.
* 중요도 수정은 로그(JSONL)와 DB(SQLite) 양쪽에 반영한다. (`UpdateRequestImportanceWeight`)
* 1회성 대화 프로젝트에서는 중요도 슬라이더를 비활성화한다. (`IsImportanceEditable`)

### 6.2 응답 영역에서 아티팩트 추출

* LLM 응답 셀의 텍스트를 드래그로 선택한 뒤 우클릭 컨텍스트 메뉴 `아티팩트로 추출`을 선택한다.
* 렌더링된 선택 텍스트를 **원문 마크다운 구간**으로 역매핑한다. (`MarkdownSelectionMatcher`) 블록 마커(제목/목록/인용/순서목록)와 인라인 마커(`* _ ` ~`), 줄바꿈을 정규화해 대응 원문 구간을 찾는다.
* 찾은 원문 마크다운 구간을 아티팩트 편집창(`ArtifactEditDialog`)의 내용으로 채운다. (렌더링 결과가 아니라 원문 마크다운이므로 줄바꿈/서식이 보존된다.) 편집창에서 내용을 수정할 수 있다.
* 아티팩트 유형은 콤보박스로 선택한다. (`Code, Table, Markdown, Json, Prompt, Plan, Review, Patch, Command, Log, Report, Config`)
* 제목은 필수로 입력한다.
* 저장 시 해당 대화 ID를 아티팩트의 출처 대화 ID(`SourceRequestId`)로 기록한다. (`ArtifactService.Save`)
* 저장 후 대화 본문에서 도려낸 **원문 구간**을 `[아티팩트: 제목]`으로 치환하고, 변경된 assistant 메시지를 로그(JSONL)와 DB(SQLite)에 영속화한다. (`UpdateAssistantMessageContent`) 해당 행 표시도 즉시 갱신한다.
  * 원문 구간을 찾지 못하면(매핑 실패) 아티팩트는 저장하되 치환은 생략하고 안내한다.
* 선택 영역이 없으면 안내 후 중단한다.

### 6.3 대화 수동 추가

* 대화 수동 추가는 채팅 입력창에 통합되었다. 5.5 참조. (별도 메뉴 없음)

## 7. 아티팩트 자동 저장과 뷰어

* LLM 응답에 아티팩트(`<artifact ...>...</artifact>`)가 포함되면 본문에서 분리하여 파일로 저장하고 아티팩트 목록에 추가한다. 한 응답의 여러 아티팩트는 각각 개별 파일/항목으로 저장한다.
* 응답 열에는 아티팩트 블록을 추출된 이름(`[아티팩트: 제목]`)으로 치환해 표시한다. (원본 대화 로그에는 전체 응답을 그대로 보존한다.)
* 아티팩트 목록 항목에는 제목/유형과 함께 출처 대화 ID(SourceRequestId)를 표시한다.
* 아티팩트 목록 항목을 클릭하면 뷰어를 띄운다.
* 아티팩트 뷰어 본문은 유형(type)에 따라 표시 방식을 나눈다.
  * 코드류(`Code`, `Json`, `Patch`, `Command`, `Config`, `Log`, 또는 코드 확장자 path)는 고정폭 폰트 코드 뷰어로 줄바꿈 없이 표시한다. (가로/세로 스크롤)
  * 그 외(`Markdown`, `Table`, `Plan`, `Review`, `Report`, `Prompt` 등)는 마크다운으로 렌더링한다. (Markdig.Wpf 사용, 링크 클릭 시 기본 브라우저로 연다.)
  * 코드 뷰어는 좋은 코드 뷰어 라이브러리를 우선 검토하되, 환경에서 사용 불가하면 고정폭 폰트 텍스트 뷰어로 대체한다. (현재 고정폭 텍스트 뷰어 사용)
* 아티팩트 뷰어는 `[삭제] [복사] [닫기]` 버튼을 가진다. `[복사]`는 원본 내용을 클립보드에 복사하고, `[닫기]`는 뷰어를 닫는다.
* `[삭제]`는 확인 후 해당 아티팩트를 레지스트리와 파일에서 제거하고(`ArtifactService.Remove`) 목록을 새로고침한다. 확인을 취소하면 아무 변경도 하지 않는다.

> 참고: 본 자동 저장 동작은 기존 산출물 승인 원칙(DEC-018)을 GUI 채팅 흐름에 한해 변경한 것이다. `Docs/4.Change_Decision_Log.md`의 DEC-039 참조.

## 8. 대화 종류와 맥락 구성

프로젝트는 생성 시 대화종류(장기/1회성)를 선택하며, `project.json`의 `long_term_conversation`에 저장된다.

### 8.1 장기 대화 (기본)

* 중요도는 LLM 평가값(0~10)을 저장한다.
* 채팅 응답 후 맥락 압축을 수행한다. 단, 중요도 2 이하는 압축을 생략한다(요청 자체를 보내지 않음).
* 채팅 요청에 압축 롤링 요약과 **최근 user 5턴(요청+응답) 원문**을 함께 주입한다.

### 8.2 1회성 대화

* 기록(대화 로그/요청/메시지)은 장기와 동일하게 저장한다.
* 모든 중요도(가중치)를 0으로 고정한다. (중요도 슬라이더 비활성화)
* 맥락 압축을 시도하지 않는다.
* 과거 맥락(롤링 요약/최근 창)을 주입하지 않는다.

### 8.3 압축 요청 맥락

* 압축 요청에도 활성 기준을 system 메시지로 포함한다. (채팅·압축 모든 요청에 활성 기준 전달)

### 8.3.1 현재 시각 주입

* 모든 채팅 요청에 현재 시각을 system 메시지(`현재 시각: yyyy-MM-dd HH:mm:ss zzz (참고용)`)로 사용자 메시지 직전에 주입한다. (DEC-051)
* 도구 사용 여부와 무관하게 항상 주입하며, 맥락 패키지에 기록되어 재현 가능하다. 압축 요청에는 주입하지 않는다.

### 8.4 대화 저장 ID 규칙

* 채팅 요청 ID: `1, 2, 3, … n`
* 압축 추가요청 ID: `1c, 2c, … nc` (대응 채팅 ID + `c`)
